// ARCHITECTURE

Built on Bevy Patterns

ECS-first. Data-oriented. Parallel by default.

ECS in Action

RUST
use blackroad_engine::prelude::*;

// Components are just data
#[derive(Component)]
struct Position { x: f32, y: f32, z: f32 }

#[derive(Component)]
struct Velocity { x: f32, y: f32, z: f32 }

#[derive(Component)]
struct Health(f32);

// Systems are functions that query components
fn movement_system(query: Query<(&mut Position, &Velocity)>, time: Res<Time>) {
    for (mut pos, vel) in query.iter_mut() {
        pos.x += vel.x * time.delta_seconds();
        pos.y += vel.y * time.delta_seconds();
        pos.z += vel.z * time.delta_seconds();
    }
}

// Automatic parallelism — non-conflicting systems run concurrently
fn main() {
    App::new()
        .add_plugins(BlackRoadPlugins)
        .add_system(movement_system)
        .add_system(render_system)
        .run();
}

Why It's Fast

Cache-Coherent ECS

Archetypal storage keeps components of the same type contiguous in memory. CPU cache lines stay hot. No pointer chasing. No indirection. Pure sequential iteration.

Automatic Parallelism

The scheduler analyzes system access patterns and runs non-conflicting systems across all CPU cores. No manual threading. No race conditions. Rust's type system guarantees safety.

Zero-Cost Abstractions

Rust compiles high-level gameplay code to the same machine code as hand-written C. No garbage collector. No runtime overhead. No JIT warm-up. Predictable frame times.
